## 二、任务一：从零实现 Transformer

**实现要点（`task-1-transformer/src/`）**

- `attention.py`：手写 scaled dot-product attention，支持 padding mask 与因果 mask；`MultiHeadAttention` 把 q/k/v 拆成 4 个头、各自缩放后拼回。
- `block.py`：**Pre-LN** 结构 `x + Attn(LN(x))`、`x + FFN(LN(x))`，残差与 LayerNorm 均可通过开关消融。
- `model.py`：字符级词表 + CLS 起始符，序列经 4 层 TransformerBlock 后做**非 PAD 的 mean pooling**，接二分类头。
- 训练（`train.py`）：d_model=128、n_heads=4、n_layers=4、d_ff=512、max_len=256、dropout=0.1；AdamW（lr 3e-4、weight_decay 0.01）+ OneCycleLR，batch 32，12 epoch，梯度裁剪 1.0；保留 dev acc 最优权重。
- 数据：ChnSentiCorp（经 ModelScope 镜像获取），train/validation parquet。

**结果与验证**

- 最佳 dev accuracy **0.8533**（epoch 6，train loss 0.2519），高于参考线 0.85，权重存 `ckpt/best.pt`。
- 注意力数值与“手写 einsum 参考实现”最大绝对误差 **9.54e-7**；因果 mask 上三角泄漏 **0.0**。
- `src/toy_lm.py` 用一个小语言模型验证因果 mask：下三角可见、未来位完全屏蔽。
- `visualize_attention.py` 对正/负样本（含多头平均）生成 4 张注意力热力图：`figures/heatmap_positive.png`、`heatmap_negative.png`、`heatmap_positive_meanheads.png`、`heatmap_long.png`。

**复现**：`python train.py` → `python eval/run.py` → `python visualize_attention.py` → `python -m src.toy_lm`。

## 三、任务二：mini-GPT（唐诗语言模型）

**实现要点（`task-2-mini-gpt/src/`）**

- `tokenizer.py`：手写 **byte-level BPE**（目标词表 4096、min_frequency=50），训练后序列化到 `ckpt/tokenizer.json`，支持 encode/decode 无损往返。
- `rope.py`：旋转位置编码（head_dim=32）。
- `attention.py`：带因果 mask 的多头注意力，并实现 **KV cache** 的增量解码（`use_cache` 时只对新 token 计算 q 并追加 k/v）。
- `model.py`：d_model=128、n_heads=4、n_layers=3、d_ff=512、block_size=64 的 decoder-only MiniGPT。
- 训练（`train.py`）：batch 64，训练 1200 步，交叉熵 + 周期性 dev PPL 评估，保存最优权重（best PPL 30.25）。
- `sampling.py` / `generate_samples.py`：greedy、top-k(k=20)、top-p(p=0.9)、temperature=1.2 四种采样，并对比有无 KV cache 的速度。

**结果与验证**

- dev **PPL 30.27**（阈值 50，3340 个 token）。
- KV cache 与全量重算 logits 最大绝对误差 **2.86e-6**；生成 53 token 时 **0.84s vs 0.90s，加速约 1.1x**（小模型短序列，长序列收益更大）。
- 采样能稳定复现名句开头，随后因模型规模小而“自由发挥”，例如：
  - greedy：`床前明月光，牵深深涯晓……`、`春眠不觉晓。……`、`故人西辞黄鹤楼河。……`
  - top-p / temperature：同一起点下多样性明显增加。

**复现**：`python train.py`（顺带训练并保存 BPE）→ `python generate_samples.py`（样例写 `samples.txt`）→ `python eval/run.py`。

## 四、任务三：LoRA / SFT / DPO

**实现要点（`task-3-sft-dpo/src/lora.py`）**

- 手写 LoRA 线性层：低秩矩阵 A/B，缩放系数 `scaling = alpha/r`，冻结原权重，只训练旁路；提供注入（`inject_lora`，目标 `q_proj/v_proj`，r=8、alpha=16）、合并（merge）等工具。
- `train_sft.py`：基座 `Qwen2.5-0.5B`，只在 assistant 响应上计算损失（user/system/prompt 部分 label 置 -100）；batch 4 × grad_accum 4、lr 2e-4、1 epoch、AdamW + cosine。
- `train_dpo.py`：策略模型挂 LoRA，参考模型为冻结基座；损失
  `loss = -log sigmoid( beta * [ (logπ_chosen - logπ_ref_chosen) - (logπ_rejected - logπ_ref_rejected) ] )`，
  beta=0.1、batch 2 × grad_accum 8、lr 2e-5。
- 数据：MOSS-003-sft 子集做 SFT；DPO-En-Zh-20k 中文偏好对，过滤后 **500 条有效对**（`data/prepare_data.py`，脚本默认上限 1500）。
- `compare.py`：同一批问题对比 base 与 SFT，输出写 `ckpt/comparison.{json,md}`；`src/chat.py` 可加载 adapter 对话。

**结果与验证**

- 注入 48 个线性层后可训练参数 **540,672 / 494,573,440 = 0.109%**（远低于 5% 上限）。
- 损失掩码比例 **0.643**（prompt 被正确屏蔽，落在 0.2–0.9）。
- SFT 训练 loss 从约 1.24 稳定下降到 **1.18**，adapter 存 `ckpt/sft/`（96 个张量）。
- DPO reward margin 从 **0.004 稳步升到约 0.187，最终 0.167**（loss 0.69→0.62），说明模型逐渐更偏好 chosen 回答；adapter 存 `ckpt/dpo/`。
- compare 中 SFT 输出相比 base 更具指令跟随性（如分点给出“开发 AI 项目的步骤”）。

**复现**：`python data/prepare_data.py` → `python train_sft.py` → `python train_dpo.py` → `python compare.py` → `python eval/run.py`。

## 五、任务四：RAG 检索增强问答

**实现要点（`task-4-rag/src/`）**

- `chunker.py`：pypdf 抽取文本 → 去空白得到连续字符流 → **字符级滑窗切分**（建库 chunk_size=512、overlap=64）。
- `indexer.py`：本地 `bge-small-zh-v1.5` 编码（query 加 BGE 官方前缀、文档不加，CLS pooling 后 L2 归一化），FAISS `IndexFlatIP`（归一化内积等价 cosine，**1152 × 512** 维）。
- `retriever.py`：**混合检索**——BGE 稠密 top40 ∪ 手写中文字符 bigram BM25 top40，经 **RRF（k=60）** 融合取 50 候选，再交 `bge-reranker-base` 交叉精排取 top-k；reranker 不可用时自动回退融合序。
- `generator.py`：本地 `Qwen2.5-7B-Instruct`，把检索片段拼进严格“只依据资料作答”的中文提示生成答案；可用 `LLM_GEN_MODEL` 换模型。
- 语料：`data/kb.pdf`（神经网络与深度学习教材），切块 **1152 个，平均长度 512.1**；评测题 `data/gold_qa.jsonl`（30 条带 gold anchor）。

**结果与验证**

- chunking sanity：平均长度 255（256/32 设置下，期望区间 128–307）。
- gold 召回：**Recall@1/3/5/10 = 0.533 / 0.867 / 0.967 / 1.000，MRR = 0.712**，R@10 远超 0.6 通过线。
- 端到端 `answer()` 返回非空答案且带 sources，例如问“前馈神经网络的特点”，答案准确给出“信息单向传播、前馈无反馈连接、强函数逼近能力……”。

**复现**：`python data/download.py`（取 PDF）→ 首次实例化 `Retriever()` 会自动抽文本、切块并建 FAISS 索引（也可 `python -m src.retriever "为什么 Transformer 需要位置编码？"` 触发建库并检索）→ `python -m src.rag "前馈神经网络有什么特点？"` → `python eval/run.py`。

## 六、任务五：工具调用 Agent

**实现要点（`task-5-tool-agent/src/`）**

- 4 个工具（`src/tools/`）：
  - `calculator.py`：**AST 白名单**求值（绝不 eval），支持算术/一元负号/math 函数，结果统一 6 位小数。
  - `python_sandbox.py`：子进程隔离执行 Python（禁 `import os/sys`，10s 超时）。
  - `file_search.py`：按文件名/通配符/内容关键词检索，路径 resolve 后强制落在允许根目录内，可读文件内容。
  - `wiki.py`：优先中/英 Wikipedia API；当前网络 Wikimedia 不可达时，回退 Bing 站内检索百度百科 + 搜索结果摘要，并做条目相关性校验。
- `agent.py`：手写 **ReAct** 循环（思考 / 动作 / 动作输入 / 观察 / 最终答案），JSON 动作解析带容错，单步工具异常被转成“观察”反馈以实现错误恢复；本地 `Qwen2.5-7B-Instruct`（可用 `LLM_AGENT_MODEL` 或 `OPENAI_BASE_URL` 切换后端）。

**结果与验证（`data/tasks.json`，10 个任务）**

- 工具单测：calculator（`2+3*4=14`）、python_sandbox（`sum(range(10))=45`）、file_search（命中 README.md）、wiki（返回长度 > 50 的百科摘要）**全部通过**。
- 多工具端到端 **10/10 全部成功（rate 1.00）**，覆盖：
  - 纯计算并判定位数：`(123+456)*789=456831，六位数`；
  - 沙箱求和：100 以内质数和 `1060`；回文判断 `level=True，world=False`；`sqrt(2026)=45.011110`；
  - 文件：统计 `data/agent-fixtures` 下 `.md` 共 2 个、定位含 TODO 的 `todo_note.md`、读出 README 第一段；
  - 事实+计算：图灵机由 Alan Turing 于 1936 提出；Hinton 出生 1947，到 2026 年 79 岁；Transformer 发表于 2017，到 2026 年相隔 9 年（wiki→calculator 链式调用）。

**复现**：`python data/download.py`（生成 tasks.json/fixtures）→ `python src/agent.py "计算 (123+456)*789 并说明位数"` → `python eval/run.py`。

## 七、任务六：Mini Coding Agent

**实现要点（`task-6-coding-agent/src/`）**

- `mcp_server.py`：MCP 风格工具服务器，顶层导出 `list_tools()` / `call_tool()`，共 **6 个工具**：`read_file / write_file / list_dir / run_tests / git_diff / git_apply`；所有路径强制 resolve 并限制在目标 repo 内，子进程一律 list 形式、不开 shell；`python src/mcp_server.py` 可起 stdio FastMCP 服务。无 git 历史时 `git_diff` 用 `.orig` 快照生成 unified diff。
- `skill_loader.py`：扫描 `src/skills/*/SKILL.md`，YAML front-matter 提供 name/description（渐进式披露的元数据），正文按需加载；提供 `SkillLoader` 类与模块函数。共 **3 个 skill**：`code-review`、`pr-description-writer`、`test-runner`。
- `subagents/`：基类 `Subagent` 维护**独立上下文/步数预算/工具白名单**；`CodeSearchSubagent`（只读 `list_dir/read_file`，负责定位文件与函数）与 `TestExecutorSubagent`（只用 `run_tests/read_file`，解读 pytest）。
- `agent.py`：本地 `Qwen2.5-Coder-3B-Instruct`（无则回退 7B，可用 `LLM_CODER_MODEL` 覆盖）。主循环先派代码搜索子 Agent，再按 ReAct 读写/测试；第一次写文件后派测试执行子 Agent；循环结束前用同一 MCP `run_tests` 做确定性自检，全绿则加载 code-review / PR 两个 skill 产出附加交付物。对小模型常见的“内联 JSON + ```json 重复块、文件内容里未转义引号”等做了**括号配平 + 宽松 key 抽取**的健壮解析。

**结果与验证（toy-repo：`add(a,b)` 被故意写成 `return a-b`）**

- Agent 轨迹（见 `last_trace.json`、`logs/task6_run.log`）：
  1. `read_file calculator.py` 读到 `return a - b`；
  2. `write_file` 写回 `return a + b`（保留 factorial 等其余实现）；
  3. 测试执行子 Agent 跑 pytest 报“全绿”，主 Agent 随后输出最终答案；
  4. 外部独立 `pytest`：**3 passed**。
- 产出 patch：`-    return a - b` → `+    return a + b`。
- Skill 交付物：code review 给 `结论: APPROVE`；PR 描述按 `fix: …` 模板写清 Background / Root Cause / Modification。
- 自检：MCP 列出 6 工具、skill 元数据 3 条、toy-repo patch 测试全绿均通过；SWE-bench Lite 为可选进阶（未下载 parquet，自检显示 skip，不影响通过）。

**复现**：`python data/download.py`（生成 toy-repo 与 buggy 快照）→ `python -m src.agent`（端到端并写 `last_trace.json`）→ `python eval/run.py`。

## 八、过程中遇到的关键问题与解决

1. **Windows 原生库冲突**：torch 与 pandas/pyarrow、FAISS 与 OMP 的 DLL 冲突（WinError 1114 / OMP Error #15）。通过 `.venv` 内 `sitecustomize.py` 保证**先 import torch**、把 `torch/lib` 前置到 PATH，并设置 `KMP_DUPLICATE_LIB_OK=TRUE` 解决。
2. **物理内存不足导致加载 7B 崩溃（0xC0000005）**：本机物理内存仅 15.8 GB（可用约 4.8 GB），小于 7B 模型。`from_pretrained(...).cuda()` 会先把约 14.5 GB 权重整体载入 CPU 内存，在 mmap/拷贝阶段触发原生访问冲突（四个 safetensors 分片经校验均完好）。改为 `from_pretrained(..., device_map="auto", low_cpu_mem_usage=True)`，让 accelerate 按分片**直接流式上 GPU**（24 GB 显存充足），任务四/五/六的模型加载统一采用该方式，加载后生成正常。
3. **任务五提示词 `str.format` 陷阱**：系统提示含大量字面 JSON 花括号，其中一处示例漏写双括号，`.format(cwd=...)` 把 `{"expression": …}` 误当替换域，10 个任务全部 `KeyError: '"expression"'`（成功率 0）。改为占位符 `__CWD__` + `str.replace`，并统一字面花括号；随后成功率升到 0.7，再补“最终答案需逐字包含年份/布尔值”的规则后达到 **1.0**。
4. **任务六小模型动作 JSON 不规范**：3B Coder 常输出“内联 JSON + ```json 重复块、一轮两个动作”，且把含 `"""docstring"""` 的整文件塞进 JSON 时不转义引号，导致参数解析为 `{}`、工具缺参并死循环。解析器改为：先截取第一个动作块 → 字符串感知地找第一个括号配平对象（`strict=False` 容忍字面换行）→ 仍失败时按 key 宽松抽取 `path/content/patch`（手工反转义、容忍未转义引号），修复后一次写文件成功。
5. **外网受限**：Wikipedia 直连超时、HuggingFace/GitHub 不稳定。数据与模型改走 ModelScope / gh-proxy 镜像、本地 `D:\my_models`；wiki 工具实现 Bing→百度百科的检索摘要兜底，保证人物年份/论文年份类事实可查。

## 十、结论

六个任务均从零实现并通过自带自检：从最基础的 scaled-dot-product / 多头 / 因果 mask（任务一）、BPE+RoPE+KV cache 的生成式语言模型（任务二），到参数高效微调与偏好对齐（任务三）、混合检索 + 本地大模型生成的 RAG（任务四）、能稳定调用多种工具的 ReAct Agent（任务五），再到具备 MCP 工具、Skill 知识与多子 Agent 协作、可自动定位并修复 bug 的 Mini Coding Agent（任务六），形成一条从 Transformer 原理到 Agent 系统的完整实践链路。
